# DNVA MVP Scope（快速落地范围）

## MVP 的核心目标
在本地环境中，以**可追溯、可人工审核**的方式，
跑通一次完整的视频生产闭环：

数据采集/整理  
→ 选题生成（5 选 1）  
→ 脚本生成与编辑（分镜 + 素材 + 执行者）  
→ 素材任务管理  
→ 剪映粗剪工程导出  
→ 多平台发布资料包导出

MVP 的关键交付标准：
- 可运行
- 可复现
- 可追溯
- 可人工审核与编辑
- 能在剪映（CapCut CN）中打开粗剪工程

---

## MVP 必须包含的功能（Must Have）

### M1：数据采集与清洗（2.1 数据层）
- 学术数据：
  - MVP 阶段至少支持 1 个公开学术源（初期实现，后续扩展）
- 热点数据：
  - 支持人工粘贴输入（创作者观察到的热点、评论区关键词等）
- 输出：
  - `clean_dataset.json`
  - `run.json`（记录 source_manifest、时间范围、prompt 版本、模型标识）

> 注：数据源扩展策略将在后续单独评估，不作为 MVP 阻塞项。

---

### M2：选题生成（2.1 选题层）
- 你通过 UI 输入指令（选择 prompt 模板 + 参数）
- 支持多模型架构：
  - MVP 默认接入 **DeepSeek V3.2**
  - 设计上必须支持后续切换 / 多选模型
- 输出：
  - `topics_5.json`（5 条候选选题）
  - 每条选题必须引用数据源条目 ID
- UI 必须支持：
  - 查看选题对应的数据来源摘要
  - 明确选择 1 个主题进入下一步

---

### M3：脚本生成与编辑（2.2）
- 基于选定主题生成结构化脚本 `script.json`
- 脚本必须包含：
  - 台词（口播 / 字幕）
  - 分镜（scene_type、时长、镜头说明）
  - 素材清单（asset list）
  - 执行者分配（HUMAN / LLM / TOOL）
  - AI 素材的 prompt 草案（可编辑）
  - 验收标准（acceptance criteria）
- 技术要求：
  - 脚本必须是 **严格 JSON**
  - 必须通过 schema 校验
- UI 必须支持：
  - 编辑台词、分镜顺序、时长
  - 调整素材执行者
  - 编辑 AI prompt 与验收标准

---

### M4：素材任务管理（2.3 素材层）
- 根据脚本自动生成素材任务列表
- 最小任务状态机：
  - pending_prompt（待确认 prompt）
  - generating（生成中）
  - ready_review（待验收）
  - approved（通过）
  - human_pending（等待人工制作）
  - human_uploaded（人工素材已上传）
- 规则：
  - LLM / TOOL 素材必须经过你确认 prompt 才能生成
  - 允许 MVP 阶段生成“占位素材”（占位图 / 占位表格）

---

### M5：粗剪装配 + 剪映工程导出（2.3 剪辑层）
- 在素材齐备后，按 `script.json` 的顺序自动拼接时间线
- 导出可在剪映（CapCut CN）本地打开的草稿工程
- MVP 最小要求：
  - 剪映可正常打开工程
  - 时间线上存在素材块（占位亦可）
- 不要求：
  - 自动精剪
  - 自动转场、调色、音频处理

---

### M6：多平台发布资料包（2.4）
- 生成并导出 `publish_pack.zip`
- 覆盖平台：
  - 抖音
  - 小红书
  - B站
  - 视频号
  - YouTube
- 包含内容：
  - 封面（多尺寸）
  - 标题候选（每平台 ≥ 5 条）
  - 简介 / 文案（按平台习惯）
  - 标签 / 话题建议
  - 合规模板（免责声明）
  - metadata.json（模型、prompt 版本、run_id）

---

## MVP 的 UI 范围（必须有，但保持轻量）
- UI 形态：**本地 Web UI**
- 用途：
  1. 查看数据源与清洗结果
  2. 选择主题
  3. 编辑脚本
  4. 审核 / 确认 AI prompt
  5. 查看素材任务状态并上传素材
  6. 触发粗剪导出与资料包导出

UI 约束：
- 不追求视觉设计
- 不做复杂前端框架
- 不做账号 / 权限系统
- local-first

---

## 明确不做（Out of Scope for MVP）
- 不做 SaaS、多用户系统
- 不做自动发布到平台（先输出资料包）
- 不做自动抓取各平台评论区 / 热榜
- 不做复杂 AI 剪辑能力
- 不做数据库（MVP 阶段仅使用 JSON + 文件目录）

---

## 质量与可追溯要求（强制）
- 每次运行生成唯一 run_id
- 所有产物落盘到 `storage/runs/{run_id}/`
- 每个输出必须记录：
  - 数据源清单
  - prompt 模板与版本
  - 模型标识（支持多模型）
  - 人工确认状态
